                    Iterable

## List — 순서 있고, 중복 허용

### ArrayList vs LinkedList

| | ArrayList | LinkedList |
|-|-----------|------------|
| 내부 구조 | **동적 배열** | **이중 연결 리스트** |
| `get(i)` | **O(1)** ✅ | O(n) ❌ |
| `add(끝)` | **O(1)** (amortized) | O(1) |
| `add(중간)` | O(n) (shift) | **O(1)** (노드만 변경) |
| `remove(중간)` | O(n) | **O(1)** |
| 메모리 | 연속 배열 (캐시 친화적) | 노드마다 prev/next 포인터 |

**🔑 면접 포인트:**
> "대부분의 경우 **ArrayList**가 유리합니다. 캐시 지역성(Cache Locality)이 좋아서 순차 접근이 빠르고, 중간 삽입/삭제가 빈번하지 않다면 ArrayList가 성능상 우위입니다."

### ArrayList 내부 동작

```java
// 초기 용량: 10 (DEFAULT_CAPACITY)
ArrayList<String> list = new ArrayList<>();

// 용량 초과 시 → 1.5배 확장 (grow)
// 기존 배열 → Arrays.copyOf → 새 배열
// 그래서 add()가 amortized O(1)
```

```
초기:     [_ _ _ _ _ _ _ _ _ _]  capacity=10
가득 참:  [a b c d e f g h i j]  size=10
확장:     [a b c d e f g h i j _ _ _ _ _]  capacity=15
```

## Map — 키-값 쌍

### HashMap 내부 구조 ⭐ (매우 빈출)

```
HashMap = 배열(bucket) + 연결리스트/레드블랙트리

bucket[0] → null
bucket[1] → Node(key1,val1) → Node(key5,val5) → null
bucket[2] → null
bucket[3] → Node(key3,val3)   ← 충돌 없음
...
bucket[n] → TreeNode (충돌 8개 이상이면 트리로 변환)
```

### HashMap 동작 흐름

```
1. put(key, value)

   hash = key.hashCode()
   index = hash & (capacity - 1)    ← 비트 연산으로 인덱스
   
   bucket[index]에 넣기:
     - 비어있으면 → 바로 저장
     - 이미 있으면 → equals()로 키 비교
       - 같은 키 → 값 덮어쓰기
       - 다른 키 → 연결리스트에 추가 (해시 충돌)

2. 충돌 개수 ≥ 8 → 연결리스트 → 레드블랙트리로 변환
   (Java 8+, 검색 O(n) → O(log n))

3. 충돌 개수 ≤ 6 → 다시 연결리스트로 변환

4. load factor(0.75) 초과 → 용량 2배 resize
```

### hashCode()와 equals() 계약

```java
// 반드시 함께 오버라이드해야 함!
// 규칙:
// 1. equals()가 true → hashCode()도 같아야 함
// 2. hashCode()가 같다고 equals()가 true는 아님 (충돌 가능)

@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof MyClass)) return false;
    MyClass that = (MyClass) o;
    return Objects.equals(this.id, that.id);
}

@Override
public int hashCode() {
    return Objects.hash(id);
}
```

**🔑 면접 포인트:**
> "hashCode()만 오버라이드하고 equals()를 안 하면, HashMap에서 논리적으로 같은 객체를 다른 키로 인식합니다. 반드시 둘 다 오버라이드해야 합니다."

### HashMap vs 그 외 Map

| | HashMap | LinkedHashMap | TreeMap | ConcurrentHashMap |
|-|---------|---------------|---------|-------------------|
| 순서 | ❌ 없음 | ✅ 삽입 순서 | ✅ 키 정렬 | ❌ 없음 |
| null 키 | O (1개) | O | ❌ | ❌ |
| 스레드 안전 | ❌ | ❌ | ❌ | ✅ |
| 시간복잡도 | O(1) | O(1) | **O(log n)** | O(1) |
| 내부 구조 | 배열+리스트/트리 | 배열+리스트+이중연결 | **레드블랙트리** | 세그먼트 잠금 |

## Set — 중복 불허

### HashSet 내부
```java
// HashSet은 사실 HashMap의 래퍼!
// 값을 key로, PRESENT(더미)를 value로 저장

private transient HashMap<E,Object> map;
private static final Object PRESENT = new Object();

public boolean add(E e) {
    return map.put(e, PRESENT) == null;
}
```

> HashSet의 동작 원리 = HashMap의 동작 원리

## 동시성 컬렉션

### ConcurrentHashMap vs Hashtable vs Collections.synchronizedMap

| | Hashtable | synchronizedMap | **ConcurrentHashMap** |
|-|-----------|-----------------|----------------------|
| 잠금 단위 | **전체** 테이블 | **전체** 맵 | **버킷(세그먼트)** 단위 |
| 동시 읽기 | ❌ (하나씩) | ❌ | ✅ (락 없이) |
| 성능 | 느림 | 느림 | **빠름** ✅ |
| null 허용 | ❌ | 키에 따라 | ❌ |

**🔑 면접 포인트:**
> "멀티스레드 환경에서 Map이 필요하면 **ConcurrentHashMap**을 사용합니다. Hashtable이나 synchronizedMap은 전체를 잠그지만, ConcurrentHashMap은 버킷 단위로 잠궈서 동시성 성능이 훨씬 좋습니다."

### CopyOnWriteArrayList
```
읽기: 락 없이 빠르게
쓰기: 배열 전체 복사 후 수정 → 느림
용도: 읽기 >>> 쓰기 (설정값 목록 등)
```

## 🎤 면접 예상 질문

**Q: ArrayList와 LinkedList의 차이를 설명해주세요.**
> "ArrayList는 내부적으로 동적 배열을 사용해 인덱스 접근이 O(1)이고, LinkedList는 이중 연결 리스트라 중간 삽입/삭제가 O(1)입니다. 하지만 실무에서는 캐시 지역성 때문에 대부분 ArrayList가 더 빠릅니다."

**Q: HashMap의 동작 원리를 설명해주세요.**
> "key의 hashCode()로 버킷 인덱스를 결정하고, 같은 버킷에 여러 키가 들어오면(해시 충돌) 연결리스트로 체이닝합니다. Java 8부터 충돌이 8개 이상이면 레드블랙트리로 변환해 검색을 O(log n)으로 보장합니다. load factor 0.75를 넘으면 용량을 2배로 resize합니다."

**Q: hashCode()와 equals()를 왜 함께 오버라이드해야 하나요?**
> "HashMap은 먼저 hashCode()로 버킷을 찾고, 같은 버킷 내에서 equals()로 키를 비교합니다. hashCode()만 오버라이드하면 같은 버킷에 들어가지만 equals()가 false를 반환해 중복 키로 처리됩니다."

**Q: HashMap은 스레드 안전한가요? 안전하게 쓰려면?**
> "아닙니다. 멀티스레드에서 동시에 put()하면 데이터 유실이나 무한루프(resize 시)가 발생할 수 있습니다. ConcurrentHashMap을 사용하면 버킷 단위 잠금으로 안전하면서도 높은 동시성을 보장합니다."

**Q: TreeMap은 언제 쓰나요?**
> "키를 정렬된 상태로 유지해야 할 때 사용합니다. 내부적으로 레드블랙트리라 삽입/검색이 O(log n)입니다. 범위 검색(`subMap`, `headMap`)이 필요한 경우 유용합니다."
