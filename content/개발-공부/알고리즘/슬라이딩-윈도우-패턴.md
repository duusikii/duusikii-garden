# 슬라이딩 윈도우 패턴

## 핵심 아이디어

배열/문자열에서 **연속된 구간**을 다룰 때, 구간을 한 칸씩 밀면서 조건을 확인하는 기법.

```
두 포인터 (left, right)로 윈도우를 관리:
  right 확장 → 조건 충족될 때까지
  left 축소 → 최적 구간을 찾을 때
```

---

## 기본 틀

### 최소 구간 찾기

```java
int left = 0;
int minLen = Integer.MAX_VALUE;

for (int right = 0; right < arr.size(); right++) {
    // 1. right 원소를 윈도우에 추가

    // 2. 조건 충족 시 → left 축소하면서 최솟값 갱신
    while (조건 충족) {
        minLen = Math.min(minLen, right - left + 1); // 갱신 먼저!
        // left 원소 제거
        left++;
    }
}
```

### 최대 구간 찾기

```java
int left = 0;
int maxLen = 0;

for (int right = 0; right < arr.size(); right++) {
    // 1. right 원소를 윈도우에 추가

    // 2. 조건 위반 시 → left 축소
    while (조건 위반) {
        // left 원소 제거
        left++;
    }
    
    maxLen = Math.max(maxLen, right - left + 1); // while 바깥에서 갱신
}
```

---

## "모든 종류 충족" 판단 — satisfied 카운터

### equals 비교의 함정

```
required = {abc:1, zyx:1}
temp     = {abc:3, zyx:1}  ← abc 초과!

equals → false!  하지만 실제로는 충족됨!
"같은가?" 가 아니라 "이상인가?" 를 봐야 함
```

### satisfied 카운터 패턴

```java
Map<String, Integer> required = new HashMap<>(); // 필요 개수
Map<String, Integer> temp = new HashMap<>();     // 현재 개수
int satisfied = 0;

// 추가 시
temp.merge(key, 1, Integer::sum);
if (temp.get(key).equals(required.get(key))) {
    satisfied++;  // "딱 도달"한 순간만!
}

// 제거 시
temp.merge(key, -1, Integer::sum);
if (temp.get(key) < required.get(key)) {
    satisfied--;  // "밑으로 떨어진" 순간만!
}

// 판단
if (satisfied == required.size()) → 모든 종류 충족!
```

```
핵심:
  ❌ equals() → 초과 시 실패, O(N)
  ❌ isOk() 매번 순회 → O(패턴 수)
  ✅ satisfied 카운터 → O(1)
```

## 주의사항

### 갱신 순서

```
최소 구간 찾기:
  ✅ while 안에서: 갱신 먼저 → 제거 나중 (충족 상태에서 기록)
  ❌ while 안에서: 제거 먼저 → 갱신 나중 (깨진 상태에서 기록)
```

### 구간 값 누적 금지

```
❌ output[0] = Math.min(output[0], start) → 서로 다른 윈도우 섞임
✅ 윈도우 단위로 길이 비교해서 더 짧을 때만 전체 갱신
```

## 문제: Smallest Substring Containing All Patterns

### 문제 설명

문자열 S와 패턴 배열이 주어질 때, **모든 패턴이 최소 1번씩 포함되는 가장 짧은 구간** [l, r]을 구하라.

### 풀이: 2단계 슬라이딩 윈도우

**1단계: 패턴 매칭**

```java
List<Node> arr = new ArrayList<>();
for (String pattern : patterns) {
    int index = 0;
    while ((index = s.indexOf(pattern, index)) != -1) {
        arr.add(new Node(pattern, index, index + pattern.length() - 1));
        index++;
    }
}
Collections.sort(arr, (a, b) -> a.start != b.start ? a.start - b.start : a.end - b.end);
```

**2단계: 슬라이딩 윈도우로 최소 구간**

```java
int satisfied = 0, leftIndex = 0, minLen = Integer.MAX_VALUE;
Map<String, Integer> temp = new HashMap<>();

for (int right = 0; right < arr.size(); right++) {
    temp.merge(arr.get(right).pattern, 1, Integer::sum);
    if (temp.get(arr.get(right).pattern).equals(required.get(arr.get(right).pattern))) {
        satisfied++;
    }
    
    while (satisfied == required.size()) {
        int wStart = arr.get(leftIndex).start;
        int wEnd = maxEnd; // 윈도우 내 최대 end 추적!
        if (wEnd - wStart + 1 < minLen) {
            minLen = wEnd - wStart + 1;
            output = new int[]{wStart, wEnd};
        }
        
        Node left = arr.get(leftIndex);
        temp.merge(left.pattern, -1, Integer::sum);
        if (temp.get(left.pattern) < required.get(left.pattern)) satisfied--;
        leftIndex++;
    }
}
```

### 엣지 케이스: maxEnd

```
start 기준 정렬이라 end가 순서대로가 아님!
  (1, "abcdefgh"): end=8
  (3, "xy"):       end=4
  → right의 end가 항상 최대가 아님!
  → 윈도우 내 모든 노드의 end 중 최댓값을 추적해야 함
```

### 복잡도

- 시간: O(S × 패턴 수 + M log M) (M = 총 매칭 수)
- 공간: O(M)
- 패턴이 많으면 Aho-Corasick으로 1단계 최적화 가능
