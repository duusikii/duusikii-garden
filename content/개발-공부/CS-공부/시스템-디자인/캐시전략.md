# 캐시 전략

## 캐시 패턴
### Cache-Aside (Lazy Loading)
```
1. 캐시 조회
2. 캐시 미스 → DB 조회
3. 결과를 캐시에 저장
4. 반환
```
- 가장 많이 쓰임, 필요한 것만 캐싱

### Write-Through
- DB 쓸 때 캐시도 같이 업데이트
- 항상 최신 데이터, 쓰기 지연 있음

### Write-Back
- 캐시에 먼저 쓰고 나중에 DB 반영
- 빠른 쓰기, 데이터 유실 위험

## 캐시 문제
- **Cache Miss**: 캐시에 없어서 DB 조회
- **Cache Stampede**: 동시에 캐시 만료 → DB 폭주
- **Cache Aside Inconsistency**: 캐시 ↔ DB 불일치

## TTL 전략
- 너무 짧으면 캐시 효과 없음
- 너무 길면 데이터 불일치
- 랜덤 TTL로 Stampede 방지

## ❓ 면접 질문
**Q. 캐시 일관성 어떻게 유지하나요?**
> DB 업데이트 시 캐시 삭제(Invalidation) 또는 동시 업데이트.

**Q. Redis 영속성 설정은?**
> RDB(스냅샷): 주기적 덤프 / AOF: 모든 명령 로그.
> 중요 데이터는 AOF + RDB 함께 사용.
