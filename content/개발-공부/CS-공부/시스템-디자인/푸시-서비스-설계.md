# 푸시 서비스 설계

## 요구사항

### 기능 요구사항
- 개별 푸시 (주문 완료, 배송 시작 등)
- 대량 푸시 (프로모션, 전체 공지)
- 다채널: FCM (Android), APNs (iOS), Web Push
- 푸시 수신 동의/거부 관리
- 예약 발송

### 비기능 요구사항
- 대량 발송: 수백만 건 동시
- 낮은 지연: 개별 푸시 수 초 내 도착
- 유실 최소화
- 중복 발송 방지

## 핵심 컴포넌트

### 1. 디바이스 토큰 관리

| user_id | token | platform | active |
|---------|-------|----------|--------|
| user1 | fcm_xxx | ANDROID | ✅ |
| user1 | apns_yyy | IOS | ✅ |
| user2 | fcm_zzz | ANDROID | ❌ |

- 유저 1명 = 여러 디바이스 가능 (폰 + 태블릿)
- 토큰은 만료/갱신됨 → **앱 실행 시마다 갱신**
- FCM/APNs에서 "Invalid Token" 응답 → `active=false` 처리
- 푸시 거부 유저 필터링

### 2. 개별 푸시 (이벤트 기반)

```
주문 완료 → Kafka 이벤트 → 푸시 워커 → 토큰 조회 → FCM/APNs → 📱 도착!
```

- 각 서비스(주문, 배송 등)가 Kafka에 이벤트 발행
- 푸시 워커가 구독하여 처리
- 지연: 이벤트 발생 → 푸시 도착 **수 초 이내**

### 3. 대량 푸시 (프로모션) — 가장 어려운 부분!

```
대상자 추출 → 배치 분할 → Kafka 파티션 분산 → 워커 병렬 → FCM 배치 API
(600만 명)  (1000건×6000) (10개 파티션)      (10대)      (500건/요청)
```

**처리량 계산:**
- 워커 10대 × 초당 1,000건 = 초당 1만 건
- 600만 건 ÷ 1만 = **10분 내 완료!**

**FCM 배치 API:**
- `sendEach()`로 최대 500건 한 번에 전송
- 개별 호출 대비 네트워크 왕복 500배 감소

### 4. 실패 처리 + 재시도

| FCM/APNs 응답 | 처리 | 재시도 |
|---------------|------|--------|
| ✅ 200 성공 | 완료 | ❌ |
| ⚠️ 429 Rate Limit | 지수 백오프 | ✅ 최대 3회 |
| ⚠️ 500 서버 에러 | 지수 백오프 | ✅ 최대 3회 |
| ❌ 404 Invalid Token | 토큰 비활성화 | ❌ 영구 실패 |

- 3회 실패 → **DLQ(Dead Letter Queue)**로 이동 → 나중에 재처리
- 발송 이력 `push_logs` 테이블에 저장 (추적 + 분석)

### 5. 중복 발송 방지

- 멱등키: `{campaignId}:{userId}`
- Redis SET에 저장 (TTL 24시간)
- 이미 발송했으면 스킵!

### 6. Rate Limiting

| 플랫폼 | 제한 | 대응 |
|--------|------|------|
| FCM | 프로젝트당 분당 ~60만 건 | Token Bucket으로 속도 제어 |
| APNs | 초당 수천 건 | 429 응답 시 백오프 |

### 7. 예약 발송

- DB에 예약 정보 저장 (`scheduled_at`)
- 스케줄러가 매분 체크 → 시간 되면 Kafka에 발행
- 또는 Redis Sorted Set (`score = 발송 시각`) + 폴링

## 면접 답변 정리

> **한 줄 요약:** "Kafka로 발송 요청을 큐잉하고, 다수의 워커가 병렬로 FCM/APNs 배치 API를 호출합니다. 대량 발송은 대상자를 배치 단위로 분할하여 Kafka 파티션에 분산하고, 워커를 스케일 아웃하여 처리량을 확보합니다."

| 질문 | 답변 |
|------|------|
| 600만 건을 어떻게 빨리? | 배치 분할 + Kafka 파티션 + 워커 병렬. FCM 배치 API로 500건씩, 워커 10대면 10분 내 완료 |
| 실패하면? | 429/500은 지수 백오프 재시도, Invalid Token은 비활성화, 3회 실패 시 DLQ |
| 중복 발송? | campaignId+userId 멱등키를 Redis에 저장 |
| 토큰 만료 관리? | 앱 실행 시 갱신 + FCM Invalid Token 응답 시 비활성화 |
