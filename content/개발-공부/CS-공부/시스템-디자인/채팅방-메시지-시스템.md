# 채팅방 메시지 시스템

채팅방에 메시지를 보내고, 목록을 조회하고, 읽지 않은 메시지 수를 관리하는 시스템.

## 핵심 기능

1. **sendMessage**: 채팅방에 메시지 전송
2. **getMessages**: 커서 기반 페이징 조회
3. **markAsRead**: 읽음 처리
4. **getUnreadCount**: 읽지 않은 메시지 수

## 설계 포인트

### 커서 기반 페이징 (offset 아닌 beforeId)

```
offset 방식: "100번째부터 20개"
  → 중간에 메시지 추가되면 중복/누락 발생!
  → 채팅처럼 실시간 데이터에 부적합

cursor 방식: "id=50 이전 20개"
  → 메시지가 추가돼도 정확
  → 채팅, SNS 피드 등 실시간 데이터에 필수
```

### 읽지 않은 수 관리

```
❌ 메시지별 읽음 상태 저장 → 메모리 폭발
✅ 유저별 마지막 읽은 메시지 ID 하나만 저장 → O(1) 공간
   → 마지막 읽은 ID 이후 메시지 개수 = 읽지 않은 수
```

### 메시지 ID는 시간순 Auto Increment

별도 timestamp 비교 없이 ID만으로 순서 판단 가능.

## 구현

```java
import java.util.*;

public class ChatSystem {

    private static class Message {
        long id;
        String roomId;
        String senderId;
        String content;
        long timestamp;

        Message(long id, String roomId, String senderId, String content) {
            this.id = id;
            this.roomId = roomId;
            this.senderId = senderId;
            this.content = content;
            this.timestamp = System.currentTimeMillis();
        }
    }

    private long messageIdCounter = 0;
    // 채팅방별 메시지 목록 (시간순)
    private Map<String, List<Message>> roomMessages = new HashMap<>();
    // 유저별 마지막 읽은 메시지 ID (roomId:userId → messageId)
    private Map<String, Long> lastReadId = new HashMap<>();

    // 메시지 전송
    public Message sendMessage(String roomId, String senderId, String content) {
        Message msg = new Message(++messageIdCounter, roomId, senderId, content);
        roomMessages.computeIfAbsent(roomId, k -> new ArrayList<>()).add(msg);
        // 보낸 사람은 자동 읽음 처리
        lastReadId.put(roomId + ":" + senderId, msg.id);
        return msg;
    }

    // 메시지 조회 (커서 기반 페이징)
    public List<Message> getMessages(String roomId, Long beforeId, int limit) {
        List<Message> messages = roomMessages.getOrDefault(roomId, new ArrayList<>());
        if (messages.isEmpty()) return new ArrayList<>();

        int endIndex = messages.size();
        if (beforeId != null) {
            for (int i = messages.size() - 1; i >= 0; i--) {
                if (messages.get(i).id < beforeId) {
                    endIndex = i + 1;
                    break;
                }
            }
        }

        int startIndex = Math.max(0, endIndex - limit);
        List<Message> result = new ArrayList<>(messages.subList(startIndex, endIndex));
        Collections.reverse(result); // 최신순 반환
        return result;
    }

    // 읽음 처리
    public void markAsRead(String roomId, String userId, long messageId) {
        String key = roomId + ":" + userId;
        Long current = lastReadId.getOrDefault(key, 0L);
        if (messageId > current) {
            lastReadId.put(key, messageId);
        }
    }

    // 읽지 않은 메시지 수
    public int getUnreadCount(String roomId, String userId) {
        String key = roomId + ":" + userId;
        long lastRead = lastReadId.getOrDefault(key, 0L);
        List<Message> messages = roomMessages.getOrDefault(roomId, new ArrayList<>());

        int count = 0;
        for (int i = messages.size() - 1; i >= 0; i--) {
            if (messages.get(i).id <= lastRead) break;
            count++;
        }
        return count;
    }
}
```

## 면접 포인트

- **"왜 커서 페이징?"** → 실시간 데이터에서 offset은 중복/누락 발생
- **"읽지 않은 수 어떻게?"** → 마지막 읽은 ID 하나만 저장, 이후 개수 카운트
- **"메시지 ID 전략?"** → Auto Increment로 순서 보장. 분산 환경에서는 Snowflake ID
- **"확장하려면?"** → 채팅방별 파티셔닝, Redis Pub/Sub로 실시간 전달
