# 인덱스 (Index)

## 개념
- 데이터 조회 속도 향상을 위한 자료구조
- 책의 목차와 같은 역할
- 내부 구조: **B-Tree** (범위 검색), **Hash** (등호 검색)

## 인덱스 장단점
| | 장점 | 단점 |
|-|------|------|
| SELECT | 빠름 ✅ | |
| INSERT/UPDATE/DELETE | | 느림 ❌ (인덱스도 갱신) |
| 저장 공간 | | 추가 공간 필요 |

## 인덱스를 써야 할 때
- WHERE 절에 자주 쓰이는 컬럼
- JOIN 조건 컬럼
- ORDER BY 컬럼
- 카디널리티(중복 적음)가 높은 컬럼

## 실행계획 확인
```sql
EXPLAIN SELECT * FROM users WHERE email = 'test@test.com';
-- type: ALL (풀스캔) → index (인덱스 스캔) 으로 개선
```

## ❓ 면접 질문
**Q. 인덱스가 있는데도 느린 경우는?**
> 1. 함수 사용: WHERE YEAR(created_at) = 2024 → 인덱스 무효
> 2. 앞에 % 사용: WHERE name LIKE '%홍길동' → 풀스캔
> 3. 카디널리티 낮음: WHERE gender = 'M' → 인덱스 효과 없음

**Q. 복합 인덱스 순서가 중요한 이유는?**
> (A, B) 인덱스는 A 단독 또는 A+B 쿼리에서만 사용 가능.
> B 단독 쿼리에서는 사용 불가. 선두 컬럼부터 탐색.
